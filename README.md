# FunPay Seller

Веб-приложение для продавца FunPay: статистика продаж, бот с ИИ для чатов,
песочница для проверки бота, управление друзьями Steam, логи и выгрузка базы.
Всё настраивается и запускается из браузера.

Стек: React + Vite (frontend), FastAPI (backend), MongoDB, Docker Compose.

## Запуск

Нужен Docker Desktop (Windows/macOS) или Docker Engine (Linux).

```bash
git clone <адрес репозитория> funpay-seller
cd funpay-seller
docker compose up -d --build
```

Откройте http://localhost:8080, создайте администратора (первый вход), затем
заполните **Настройки**:

| Вкладка | Что нужно |
|---|---|
| FunPay | cookie `golden_key` и User-Agent браузера |
| ИИ (Яндекс) | API-ключ сервисного аккаунта, folder id, модель |
| Steam | ключ Web API, свой Steam ID; для удаления друзей — cookie `steamLoginSecure` и `sessionid` |
| Бот | задержка ответа, лимиты токенов, шаблоны, заметки продавца |
| Друзья | защищённый список, сколько слотов держать свободными |

Ключи хранятся в MongoDB в зашифрованном виде. Ключ шифрования создаётся при
первом запуске в volume `app-data` — не удаляйте этот volume, иначе ключи
придётся ввести заново.

По умолчанию сайт открыт только на этом компьютере. Чтобы открыть его в
локальной сети, создайте `.env` из `.env.example` и поставьте
`APP_BIND=0.0.0.0`.

## Обновление

```bash
./update.sh          # Linux/macOS
.\update.ps1         # Windows PowerShell
```

Скрипт делает `git pull` и `docker compose up -d --build`. База и настройки
лежат в volumes и сохраняются.

## Что умеет

- **Продажи.** Кнопка синхронизации: первый раз выгрузка «за всё время»
  через встроенный экспорт FunPay, дальше — с даты последней оплаты (или с
  самого старого незакрытого заказа, чтобы обновить его статус). Отчёт с
  графиками и фильтрами — из наших наработок (`legacy/`).
- **Бот.** Опрашивает чаты, склеивает сообщения подряд (задержка + потолок
  ожидания), перед отправкой проверяет, не дописал ли покупатель. Промпт на
  английском, ответы на русском. Инструменты: открытые заказы, ассортимент с
  остатками, детали заказа, сохранение Steam-ссылки (проверка в коде),
  передача чата продавцу. Лимиты: токены в сутки, ответы на чат, ИИ только при
  открытом заказе, обрезка сообщений, `max_tokens`, шаблоны без ИИ.
- **Типы товаров** («Настройки → Типы товаров»): способ выдачи (подарок,
  обмен, аккаунт, другое), описание для ИИ-классификации, инструкция для ИИ
  «как работать с покупателем», слова-ключи и слова «сразу владельцу».
  Готовые пресеты: подарок Dota 2 (30 дней дружбы, 8 подарков в день),
  обмен по трейд-ссылке, аккаунт Dota 2, «другое».
- **Лоты** (страница «Лоты»): карточки с FunPay вместе с описанием; тип
  определяется ручным выбором → словами-ключами → ИИ по описанию → по
  умолчанию. Тип заказа берётся у лота с тем же названием.
- **Сроки и очередь подарков**: дата, когда Steam разрешит дарить (дружба
  N дней), плюс лимит подарков в день — очередь сдвигается, если день занят.
- **Аккаунты**: в карточке лота типа «аккаунт» — форма логин/пароль/почта.
  Данные сразу уходят в автовыдачу лота на FunPay и у нас не хранятся (ни в
  базе, ни в логах). Если покупатель пишет о проблеме со входом, чат сразу
  уходит владельцу без ИИ.
- **Промпт.** Правила общения, заметки и примеры ответов редактируются в
  «Настройки → Промпт»; правила работы с инструментами зашиты в код.
- **Шаблоны по фразам.** Шаблон срабатывает, если сообщение похоже на одну
  из фраз-примеров (порог настраивается); `{buyer}` подставляет ник.
- **Песочница.** Покупатели, лоты и заказы без FunPay, плюс симуляция
  дружбы в Steam для проверки сроков подарка. Бот отвечает тем же
  конвейером, видно каждый вызов инструмента и расход токенов.
- **Друзья Steam.** Порядок важности: защищённые → с открытым заказом →
  давние покупатели → покупатели → друзья (по уровню Steam) → заявки.
  Удаление — только снизу и только с подтверждением; автоочистка выключена по
  умолчанию.
- **Автоподнятие лотов** («Настройки → FunPay»): категории из продаж или
  вручную, следующий подъём — по сроку, который сообщает FunPay.
- **Уведомления в Telegram**: когда инструмент бота вернул ошибку или чат
  передан продавцу. Без Telegram бот просто отвечает покупателю, событие
  остаётся в логах.
- **Удаление друзей** можно полностью отключить («Настройки → Друзья»).
- **Логи** в базе (30 дней): каждый запрос к API, каждый вызов Steam,
  FunPay, ИИ и Telegram (код ответа и время), каждый вызов инструмента,
  изменения настроек (без значений), входы, ошибки фронта. Частые опросы
  страниц пишутся только при ошибке. Фильтры и скачивание JSONL. **Выгрузка базы** в
  ZIP (без паролей и ключей).

## Готовые библиотеки

- [funpaybotengine](https://github.com/funpayhub/funpaybotengine) (MIT) —
  чаты, отправка сообщений, продажи и лоты FunPay. От авторов FunPay Hub.
- Экспорт продаж FunPay — свой код (`app/integrations/funpay/exports.py`),
  проверен на реальном аккаунте.
- Steam — официальный Web API + `actions/RemoveFriendAjax` с cookie. Готовые
  Python-библиотеки ([ValvePython/steam](https://github.com/ValvePython/steam))
  работают через протокол клиента Steam и требуют логина с паролем и 2FA, что
  нам не подходит.
- YandexGPT — OpenAI-совместимый API AI Studio через `httpx`.

## Что ещё не проверено на живых аккаунтах

- Чат FunPay через funpaybotengine (опрос, отправка, лоты) — код по API
  библиотеки, но на настоящем аккаунте не запускался. Начните с песочницы,
  затем включите бота и смотрите «Логи».
- Страница заявок Steam (`/friends/pending`) разбирается по разметке —
  при изменении вёрстки заявки просто не будут видны.
- Вызов функций в YandexGPT: Яндекс пишет, что надёжнее всего на
  `yandexgpt/latest` (Pro 5); на lite-модели проверьте в песочнице.
- Условия FunPay и Steam об автоматизации — прочитайте сами перед включением.

## Разработка

```bash
cd backend
python -m venv .venv && .venv/Scripts/pip install -r requirements-dev.txt
.venv/Scripts/python -m pytest          # тесты на реализациях в памяти
.venv/Scripts/ruff check app tests

cd ../frontend
npm install && npm run dev               # http://localhost:5173, /api → :8000
```

Тесты репозиториев против настоящей MongoDB:

```bash
docker compose --profile test run --rm backend-tests
```

Устройство backend (как в ran-earth): `models` → `repositories`
(`base` / `memory` / `mongo`) → `usecases` → `application` (роуты), внешние
сервисы — в `integrations` за интерфейсами (`BaseMarketplace`,
`BaseSteamGateway`, `BaseLLM`, `BaseOrderExporter`). Тесты подменяют их
рабочими реализациями в памяти (`SandboxMarketplace`, `MemorySteamGateway`,
`ScriptedLLM`), без `unittest.mock`.

Старый CLI для выгрузки и HTML-отчёта лежит в `legacy/`.
